# AGENTS.md: guide for contributors and AI agents

photobaer is a browser image editor (PWA) that aims at Photoshop parity: the same menus, shortcuts, behaviour and
PSD fidelity. A Rust engine compiled to WebAssembly runs in a web worker; a React UI renders the canvas with WebGPU
(WebGL2 fallback). Read this file first, then [docs/PLAN.md](docs/PLAN.md).

## 2. Repository map

```text
engine/              Rust engine (document model, compositor, filters, brushes, ICC), built to wasm
app/src/
  engine.worker.ts   worker API: every editor command the UI, actions, scripts and MCP call
  worker/            worker types and helpers
  engine-pkg/        generated by `pnpm build:engine` (gitignored, never edit)
  render/            WebGPU and WebGL2 display, WGSL compositor
  psd/               PSD mapping on top of ag-psd (depths, channels)
  app/               menus, shortcuts, dialogs, tool hooks, agent bridge
  shell/             toolbar, options bar, panels, color widgets
  locales/<locale>/  PO catalogs (en is the source, pseudo is for testing)
app/public/          static site pages, icons, service worker, crawler files
mcp/                 photobaer-mcp (MIT, own version, published to npm by the release workflow)
tests/               corpus check against Photoshop composites (tests/corpus is local only)
docs/glossary/       Photoshop terms per language, binding for translations
scripts/             Lingui node hooks, PO batch tools, third-party notices
```

## 3. Rules

1. **Own implementation.** Build from the public Photoshop user guide, the public PSD specification and observed
   behaviour. Never copy code, shaders, icons or assets. Icons come from lucide (ISC).
2. **Check licenses before adding a dependency.** The app is AGPL-3.0-only and also licensed commercially, so
   check a new license against both. Record it in `docs/PLAN.md` section 3. `scripts/third-party.mjs` builds the
   notices for everything shipped.
3. **Every user-visible string goes through Lingui** (`<Trans>`, `t`, `msg`, `plural`), with named placeholders
   and no string concatenation. Modules the engine worker imports use `msg` macros too; `pnpm build` fails if a
   macro stays untransformed. Run `pnpm i18n:extract` after changing strings.
4. **Photoshop wording.** Menu commands, tools, panels and buttons use Photoshop's names in each language
   (`docs/glossary/<locale>.tsv`). Hints and messages address the user informally where the language has a choice.
5. **Cross-origin isolation.** The engine needs `SharedArrayBuffer`, so every host must send COOP `same-origin` and
   COEP `require-corp` (`vite.config.ts`). Do not add resources that break that.
6. **Tests come with the change.** Rust tests live in `engine/src/*_tests.rs` and modules; app tests are
   `*.test.ts` next to the code and run with `node --test`.
7. **Changelog.** User-visible changes get a line under `## [Unreleased]` in `CHANGELOG.md`
   ([Keep a Changelog](https://keepachangelog.com/en/1.1.0/)). The release workflow uses the version's section
   as release notes and fails without one.
8. **Contributions need the CLA** ([CLA.md](CLA.md)).

## 4. Commands

| Command | What it does |
|---|---|
| `pnpm build:engine` | Builds the Rust engine to wasm and runs wasm-bindgen into `app/src/engine-pkg` |
| `pnpm dev` | Vite dev server (sends the isolation headers) |
| `pnpm test` | `cargo test` for the engine, then all node tests |
| `pnpm typecheck` | `tsc --noEmit` |
| `pnpm corpus` | Compares PSD renders with Photoshop's composites in `tests/corpus` (local files) |
| `pnpm build` | Engine, typecheck and production build into `dist/` |
| `pnpm i18n:extract` | Updates the PO catalogs |

Prerequisites: Rust stable with `wasm32-unknown-unknown`, `wasm-bindgen-cli` 0.2.129 (same as `engine/Cargo.lock`),
Node.js 24, pnpm 10.

## 5. Before you finish

```sh
pnpm typecheck
pnpm test
pnpm build       # if you touched the worker, i18n or the build
pnpm corpus      # if you touched PSD, the compositor or blending, and you have the corpus
```

Check UI changes in the browser (Chrome or Edge, WebGPU) with `pnpm dev`, and watch the console for errors.
