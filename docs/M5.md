# M5 Filters and retouch: spec

Milestone text and gates: `docs/PLAN.md` sections 4 and 5. Behavior and look follow the public
Photoshop user guide and the owner decisions below. Everything here is written in our own words;
option names are the common industry terms. The behavior choices are listed in section 12.
Algorithms are our own implementations of the behavior described here.

Status: accepted by the owner 28 September 2026 (all section 13 recommendations, D1-D14; D13: the four unplaced tools stay out of M5).

## 0. Out of M5 scope (named so nobody builds them by accident)

- Camera Raw Filter, Adaptive Wide Angle, Lens Correction: M6 (PLAN M6 lists RAW develop, lens
  correction and adaptive wide angle). The Filter menu shows no entries for them in M5 (D1).
- Face-Aware Liquify (face detection and landmarks): M7 AI. The Liquify dialog ships without the
  face section (D9).
- Mixer Brush, Background Eraser, Magic Eraser, Color Replacement: in the PLAN tool inventory but in
  no milestone line; owner to place them (D13).
- Filters on 16-bit channels beyond what the tile store already carries, 32-bit, CMYK, Lab and other
  modes: M6. M5 filters run on RGB(A) and on 8- and 16-bit tiles the engine already has.
- Content-Aware Fill workspace with a painted sampling area and output to a new layer, Remove tool,
  generative fill: not planned; none in M5 (D10).
- Filter plug-ins (8BF), Filter > Browse Filters Online: not planned.
- GPU (WGSL) filter kernels: filters run on the CPU path in the engine (D5).

## 1. Filter model and format (engine)

**Registry.** A new engine module `engine/src/filters/` holds one registry entry per filter id:
`{ id, label, group, params schema (key, kind number|int|percent|angle|select|bool|point|curve|
kernel|editor, min, max, step, unit, choices, default), reach(params) -> px per side, execution
point|local|global, alpha kept|processed, preview true|false, rgb_only }` and an `apply(plane,
params, ctx)` over an f32 RGBA plane (straight alpha, 0..1). `ctx` carries the document-space
origin of the plane, the layer bounds, the seed (D4), the foreground and background colors, and
optional extra planes (displacement map, texture). The registry is exported to the app as JSON
(`filter_schema()`), so dialogs, menus and validation come from one table (D3).

**Stored filter.** A filter instance is `{ kind: "<group>.<name>", params: {...} }` (JSON). The M3
kinds keep their tags and parameter JSON, so every v5 file reads unchanged (the 16 adjustment kinds
and Gaussian blur become registry entries). Params are validated against the schema on every entry
point: unknown key, wrong type or a value outside min..max is an error naming the filter and key.
Large params (Liquify mesh, Vanishing Point stamps, displacement map pixels) live in document blobs (M3 blob store) and the params hold the blob id.

**Runner.** Destructive apply on a pixel layer (or its mask, or the quick mask) runs over the
selection bounds grown by `reach`, tile by tile in document coordinates, reading neighbor tiles
for the reach. `global` filters (Average, Clouds, Difference Clouds, Fibers, Equalize-like
statistics, Lens Flare, Lighting Effects, Tree, Flame, Picture Frame, content-aware ops) read the
whole layer bounds (or the document rect for render filters on an empty layer) once. `alpha kept`
filters change color only. The result mixes onto the source by the selection coverage (M3 D12 rule,
feathered selections mix partially). One undo step labelled with the filter name. On a smart object
the same command appends a smart filter (M3 section 7); every M5 filter is smart-filter capable.
Shape, text, fill and adjustment layers refuse with the M4 "must be rasterized" error.
Locked pixels refuse naming the layer.

**Randomness.** Every filter with random output (Add Noise, Clouds, Difference Clouds, Fibers,
Diffuse, Mezzotint grainy types, Wave randomize, Crystallize, Pointillize, Fragment, Tiles, Extrude,
Tree, Flame, gallery grain/texture effects, blur gallery noise) takes its values from
`hash(seed, doc_x, doc_y, channel)`, never from a sequential RNG, so a tile rendered alone equals
the same tile of the whole-layer render and a smart filter re-renders identically after reload
(D4). `seed` is a param (u32) written on apply.

**Manifest v6** (D2) in one bump in B1: filter kinds as registry tags with schema-validated params,
blob-backed params, `seed`, the Filter Gallery stack entry, the liquify/puppet/perspective-warp
smart filter entries, and nothing else. v1-v5 files open unchanged.

## 2. Filter commands, dialogs, preview, Last Filter, Fade

**Menu.** Filter menu order: Last Filter (Ctrl+Alt+F), separator, Convert for Smart
Filters, separator, Filter Gallery..., Liquify... (Ctrl+Shift+X), Vanishing Point... (Ctrl+Alt+V),
separator, submenus Blur, Blur Gallery, Distort, Noise, Pixelate, Render, Sharpen, Stylize, Video,
Other, with the entries and order of the catalogue (section 14). Entries with parameters end in
"...". Entries are disabled without a document or when the target refuses (section 1).

**Dialog.** One generic parameter dialog built from the schema (sliders with number fields, selects,
checkboxes, angle dial, point picker on the canvas for `point`, curve editor for Shear, 5x5 grid
for Custom), a Preview checkbox (on by default), OK, Cancel, Reset (Alt turns Cancel into Reset).
Filters without parameters run at once. Live preview renders into the canvas preview path for the
visible rect only. Each change cancels the pending render and starts a new one after 16 ms: first an
interactive render, on a downsampled proxy with px params scaled when the visible target area
exceeds 262144 px, then a full-resolution render of the visible rect 350 ms after the interactive
one finished. OK applies at full resolution over the whole target.
Render filters marked `preview false` (Clouds, Difference Clouds, Fibers) show no live preview.
Budget gate: preview under 200 ms on the viewport (PLAN section 5).

**Last Filter.** Repeats the last applied filter command with the same params on the current
target without a dialog. The menu label stays "Last Filter" (Ctrl+Alt+F). The entry is enabled with
a document; before any filter ran in this session it reports "No filter to reapply.". A filter is
recorded only when its apply succeeded.

**Fade** (Edit > Fade..., Ctrl+Shift+F). Available after any history step when the active layer is
a pixel layer that also exists as a pixel layer in the previous state. Dialog: Opacity 0..100 %
(default 100), Mode (all layer blend modes). Normal: per pixel `a = a_cur x o`, `b = a_prev x
(1 - o)`, color `(cur x a + prev x b) / (a + b)`, alpha `a + b`; other modes composite the current
pixels over the previous ones in that mode at opacity `o`. Live preview, one undo step "Fade".
Messages: "There is nothing to fade.", "Fade needs a pixel layer.", "The previous state
has no matching layer to fade toward." Dialog title "Fade <step label>".

## 3. Filter behavior notes (catalogue in section 14)

Formulas below are the behavior contract for the goldens; everything else follows the catalogue
params and the public Photoshop guide descriptions.
- Blur: 3x3 kernel 1-2-1 / 2-4-2 / 1-2-1 over 16, edges clamped, alpha included. Blur More: Blur
  three times. Average: every pixel (inside the selection) becomes the mean color.
- Sharpen: 3x3 cross kernel center 5, four neighbors -1. Sharpen More: center 9, eight neighbors -1.
  Sharpen Edges: Sharpen weighted by 3x edge strength (clamped to 1).
- Unsharp Mask: `x + amount * (x - gaussian(x, radius))` where `|x - blur| > threshold`.
  High Pass: `x - gaussian(x, radius) + 0.5`.
- Solarize: `v < 0.5 ? 2v : 2(1 - v)` per color channel, alpha kept.
- Mosaic: cells of `cellSize` aligned to the document origin, each cell its mean.
- Offset: shift by (h, v) px with wrap around, repeat edge pixels, or background color.
- Median / Minimum / Maximum: radius r square window (Minimum/Maximum: squareness or roundness).
- Add Noise: per pixel and channel `amount x (u - 0.5)` (uniform) or `amount x 0.4 x g` (gaussian,
  g standard normal), monochromatic uses one value for all channels, alpha kept.
- Twirl: rotation `angle x (1 - d/R)^2` inside `R = min(w, h)/2` around the layer center; Pinch,
  Spherize, Polar Coordinates, Ripple, Wave, ZigZag, Shear, Displace are inverse-mapped with
  bilinear sampling and the listed undefined-area rule.
- Render filters draw on the layer (Clouds uses foreground and background colors; Difference Clouds
  blends clouds in Difference). Tree, Flame and Picture Frame render procedural art into the layer
  (own generators, D7).
- Gallery effects are painterly approximations (D7), built from shared primitives (edge detect,
  posterize, stroke directions, texture maps canvas/burlap/brick/sandstone plus frosted/tiny lens
  for Glass, light direction relief).

## 4. Filter Gallery

Dialog with a large preview, the effect list grouped Artistic, Brush Strokes, Distort, Sketch,
Stylize, Texture (47 effects, section 14), the selected effect's params, and an effect-layer stack
(New Effect Layer, Delete, Move Up, Move Down, per-layer enable checkbox "<filter> enabled"). The
stack applies bottom to top; an empty stack says "Pick a filter to start a stack."; a filter without
options says "This filter has no options." Destructive apply = one step "Filter Gallery"; on a smart
object one smart filter entry holding the stack. Opening the dialog again from a smart filter entry
restores the stack.

## 5. Blur Gallery

Field Blur, Iris Blur, Tilt-Shift, Path Blur, Spin Blur (catalogue params). Each opens its dialog
with on-canvas handles: field pins (click adds a pin, drag moves, blur per pin), iris ellipse
(center, size, aspect, roundness, feather, rotation), tilt-shift lines (center, rotation, focus and
feather widths, distortion), path blur paths (click points, end point speeds), spin ellipse
(center, size, aspect, feather, angle). Shared settings for all five: light bokeh, bokeh color,
light range min/max, noise amount/distribution/size/color/highlights, strobe strength/flashes
(section 14). Blur per pixel comes from the handle geometry (field pins by inverse-distance weight
`1/d^4`); points are stored relative to the layer bounds (0..1). One undo step per OK.

## 7. Vanishing Point

Dialog (Ctrl+Alt+V): tools Create Plane (4 clicks), Edit Plane (drag corners and edges, grid size
1..200, default 50), Stamp (clone in perspective), Hand; Create connected plane (hinge edge and
angle), Delete Plane, Undo, Redo, Show Grid. Stamp options: Diameter, Hardness 0..100 (50), Opacity
0..100 (100), Angle, Healing off / on / luminance (gap B15). Alt-click sets the stamp source inside
a plane; strokes map through the plane homographies. Planes and stamps are stored in the filter
params (blob), so the smart filter entry re-renders them. One undo step "Vanishing Point".

## 8. Healing core (engine `engine/src/heal.rs`)

- **Hole fill (PatchMatch, multi-scale).** Image pyramid by 2x2 averaging while both sides stay at
  least 2 patch widths, up to 7 levels; at the coarsest level the hole is seeded by flood from the
  border; per level: nearest-neighbor field search (random init or upsampled previous field, a
  propagation and random search with alpha 0.5, 5 iterations, patch 7 px), then 6 passes of search
  plus weighted voting (weight `1 / (error + 0.001)`) with growing weight for unknown pixels. Source
  pixels exclude the hole, transparent pixels and an optional source mask. Seeded (D4), so the same
  input gives the same output.
- **Poisson solve.** Successive over-relaxation, omega 1.8 (clamped 0.05..1.99), up to 300
  iterations, stop at residual 5e-4; gradients `source` (healing brush) or `mixed` (content-aware
  move). Coverage below 1 mixes the solved pixels in by coverage.
- **Proximity match.** Hole = mean of its border ring, then 8 rounds of box blur with a shrinking
  radius (start `max(2, round(hole extent / 3))`) that keep the known pixels.
- **Create texture.** Proximity match plus the high-frequency detail (pixel minus its blur) copied
  from a seed-dependent offset.
- **Content-aware fill.** Structure 1..7 sets patch `5 + 2 (s - 1)` and iterations `3 + s`; Color
  Adaptation 0..10 blends the PatchMatch result with a Poisson-blended version by `color / 10`.

## 10. Edit menu retouch commands and warps

- **Content-Aware Fill...** needs a selection ("Select the area to fill."); dialog Structure 1..7
  (4), Color Adaptation 0..10 (5); step "Content-Aware Fill"; no pixels: "Content-Aware Fill produced
  no pixels." **Delete and Fill Selection** (no shortcut; Shift+Backspace stays Fill...) runs it
  with 4 / 5, no dialog, and deselects. The Fill dialog's Contents list has Content-Aware (between
  Color... and Pattern) with Content-Aware Structure 1..7 (4) and Content-Aware Color 0..10 (5); it
  has no live preview and runs on OK with the dialog's mode, opacity and preserve transparency.
- **Content-Aware Scale** (Ctrl+Alt+Shift+C): dialog Width, Height 10..300 % (100), Amount 0..100 %
  (100), Protect Skin Tones. Seam carving:
  energy = luminance gradient magnitude (x0.1 where alpha < 0.5, +250 on skin-tone pixels), dynamic-programming seams removed or duplicated; Amount mixes with a plain
  resample. Step "Content-Aware Scale". Error: "Content-Aware Scale needs an unlocked pixel layer."
- **Puppet Warp**: on-canvas session on the layer content: a triangle mesh over the opaque pixels
  (grid spacing Fewer Points 32 / Normal 16 / More Points 8 px, grown or shrunk by Expansion
  -50..50 px, default 2), Mode Rigid / Normal / Distort (stiffness 2 / 1 / 0.5), Show Mesh, pins
  (click adds, drag moves, Alt-click deletes, Alt-drag near a pin rotates it, pin depth), commit
  Enter, cancel Esc. Solver: as-rigid-as-possible iterations (at most 24, stop when the largest move
  is below 1e-5). On a smart object it becomes a smart filter. Step "Puppet Warp".
- **Perspective Warp**: session with Layout mode (draw quads, join edges) and Warp mode (drag
  corners, Straighten horizontal/vertical edges, Straighten all); commit Enter. On a smart object a
  smart filter. Step "Perspective Warp".
- Messages: "Puppet Warp needs an unlocked pixel layer with content.", "Perspective Warp needs an
  unlocked pixel layer with content.", "Select an unlocked layer with pixels to warp."

in `dist/descriptor.js`): adaptive wide angle, add noise, black & white, box blur, channel mixer,
clouds, color balance, color halftone, curves, custom, de-interlace, difference clouds, diffuse,
displace, dust and scratches, emboss, exposure, extrude, fibers, gaussian blur, gradient map, high
pass, lens flare, levels, liquify, maximum, median, mezzotint, minimum, mosaic, motion blur, offset,
oil paint, perspective warp, photo filter, pinch, pointillize, polar coordinates, posterize, puppet,
radial blur, reduce noise, ripple, selective color, shape blur, shear, smart blur, smart sharpen,
spherize, surface blur, threshold, tiles, trace contour, twirl, unsharp mask, wave, wind, zigzag.
Our filters with one of these types map both ways; export of any other smart filter refuses with an

raw descriptor and the placed layer's cached pixels (as M4 D5 for text) until edited. Liquify from
PSD: the mesh bytes round-trip; rendering them needs the mesh format (gap B12).

## 12. Behavior choices and other choices (owner may overrule each)

Q1 Last Filter is Ctrl+Alt+F and repeats without a dialog (Photoshop: Ctrl+F repeats, Ctrl+Alt+F
reopens the dialog). Q2 the focus tools (Blur, Sharpen, Smudge) have no shortcut. Q3 Content-Aware
Fill is a two-slider dialog, no sampling workspace. Q4 all filters are smart-filter capable,
including Liquify, Vanishing Point and the render filters. Q5 Clone Source slots are not saved with
the document. Q6 the history brushes paint from the oldest history state; there is no source picker. Q7 Red Eye works on a click box
of 40 x 40 px when the drag is under 2 px. Q8 gallery and render art filters are own approximations
with the parameter sets of section 14 (for example Neon Glow offers four glow colors instead of a
color picker; Picture Frame has six frame types). Q9 Displace has no map source in the UI, so it leaves the layer unchanged until a map arrives from a PSD smart filter (B16).

Other choices: Liquify has no mesh files (D11); smart filter
params are schema-validated and refuse bad values instead of clamping silently; Lens Blur sizes its 8
kernels against the largest radius its params allow (not the largest in the image), and Surface/Smart
Blur pick the exact or fast path from the layer area, so a tile renders like the whole layer; Median
(and Dust & Scratches) above radius 2 slides a 4096-bin histogram, so its result is quantized to
1/4095 (below 8-bit precision).

## 13. Decisions (open, need the owner)

- (D1) Scope of "all 86 filter commands": the Filter menu has 67 submenu filters plus Filter
  Gallery (47 effects), Liquify, Vanishing Point, Camera Raw Filter, Adaptive Wide Angle and Lens
  Correction. Recommendation: M5 builds the 67 + Gallery + Liquify +
  Vanishing Point; the three camera/lens commands go to M6 with RAW develop.
- (D2) Manifest v6 in one bump in B1 (section 1). Recommendation: yes (one persistence review, the
  M3/M4 pattern).
- (D3) Filters as a data-driven registry (id string + validated JSON params) instead of 116 new enum
  variants; the 17 M3 kinds keep their tags. Recommendation: yes (one schema drives engine
  validation, dialogs, menu and PSD mapping).
- (D4) Randomness from `hash(seed, x, y, channel)` in document coordinates with a stored per-instance
  seed. Recommendation: yes (tile-exact, smart filters re-render identically, goldens possible).
- (D5) Filters on the CPU only (Rust/WASM, threads where the engine has them); preview on a
  viewport proxy above 262144 px. Recommendation: yes; GPU kernels later if the 200 ms preview
  budget fails for a filter, measured per filter.
- (D6) Healing: own multi-scale PatchMatch + SOR Poisson + seam carving as in section 8/10, no ML
  inpainting (LaMa stays M7). Recommendation: yes.
- (D7) Gallery effects, Tree, Flame, Picture Frame, Oil Paint, Lighting Effects: own
  approximations with the parameter sets of section 14; goldens are self-consistency (identity at
  neutral params, determinism, tile equality) plus a few formula checks, and a visible difference to
  Photoshop is accepted. Recommendation: yes.
- (D8) PSD: map the ag-psd filter types both ways; other smart filters refuse export by name (M3
  rule). Alternative: offer "rasterize unsupported smart filters on export". Recommendation: M3 rule.
- (D9) Face-Aware Liquify moves to M7. Recommendation: yes.
- (D10) No Content-Aware Fill workspace (sampling brush, output to new layer). Recommendation:
  no workspace in M5.
- (D11) Liquify Save/Load Mesh: decided 2 October 2026, no mesh files (no own file types; `.msh` is
  undocumented). The `.pbaer` project file was removed the same day: PSD is the only layered save,
  autosave keeps the internal manifest + tiles in OPFS.
- (D12) Clone Source slots app-wide, 5 slots, not saved. Recommendation: yes.
- (D13) Mixer Brush, Background Eraser, Magic Eraser, Color Replacement (PLAN tool list, in no
  milestone line). Recommendation: owner places them; not in M5 unless the owner adds a batch.
- (D14) Batch order: PLAN priority "blur, sharpen, noise, distort first". Recommendation: framework
  (B1), then B2 blur, B3 sharpen + noise, B4 distort + other, then retouch (B9-B11) before the art
  filters (B5-B8), then Liquify, warps, Vanishing Point, PSD.
