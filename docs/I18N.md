# photobaer localization plan (12 languages, Lingui 6, no external services)

Source item: docs/TODO.md M9 "Localization" bullet.
Languages: en (source), de, fr, es, pt-BR, ja (wave 1); ko, zh-Hans, ru, tr, pl, it (wave 2).

## Measured starting point (7 October 2026)
- No i18n library; 0 hits for i18n/useTranslation/navigator.language in app/src.
- Stack: React 19.3, Vite 8.3, @vitejs/plugin-react 6.1, TypeScript 7.0, Node 24.11.1, pnpm.
- UI text hard-coded in 57 .tsx files plus .ts tables (menus.ts, contextMenus.ts, tools.ts, tooltips.ts, typeMenu.ts, ...).
- Node unit tests run .ts files directly (`node --test`, type stripping, no Babel/SWC transform).
- Service worker precaches every built file (vite.config.ts `precache()`).

## Library decision: Lingui 6, no external services
- User decision 7 October 2026: Lingui (MIT, open source, runs only in our build and runtime); no hosted TMS or
  other external service. Translations live in the repo as PO files.
- Lingui 6.0 (22 April 2026): ESM-only, Node 22.19+/24+, Vite 8 plugin, named JSX placeholders (`<link>` not `<0>`),
  stronger TS types, multithreaded CLI. Repo has Node 24.11.1 and Vite 8.3.
- Packages: `@lingui/core`, `@lingui/react` (runtime); `@lingui/cli`, `@lingui/vite-plugin` (dev). Lingui docs list a
  native macro transform for plugin-react v6 (`lingui({ macroTransform: true })`, unverified, proven in phase 0).
- Source text in code (`<Trans>`, `t`, `msg`, `plural`), `lingui extract` writes PO catalogs per locale
  (`app/src/locales/{locale}/messages.po`), the Vite plugin compiles them, `import()` loads only the active locale.
- ICU MessageFormat 1 (plural, select, selectordinal, number). MessageFormat 2: spec Final Candidate (March 2025),
  TC39 Intl.MessageFormat at Stage 2, Lingui/FormatJS/i18next have no MF2 (Locize, May 2026).
- Rejected: Paraglide JS 2 (ships every language of each used message; photobaer is one page with thousands of
  messages); react-i18next (key-based, ICU via plugin, larger runtime); own module (re-implements extraction,
  formatter and validation).

## Late-2026 practices applied
- Source-string extraction, compile-time catalogs, per-locale lazy load, typed APIs.
- ICU plurals/select only; no string concatenation; named placeholders; translator comments and msgctxt for
  ambiguous words ("Fill" verb vs noun, "Stroke", "Layer" menu vs noun).
- Built-in Intl for everything formatted: NumberFormat (percent, units), DateTimeFormat (history, file info),
  ListFormat, DisplayNames for the picker (each language in its own name), PluralRules via Lingui.
- Locale negotiation: saved preference > navigator.languages best match > en; fallback chain pt-BR > pt > en.
- `<html lang>` follows the UI language (CJK font selection, hyphenation, screen readers).
- Layout: CSS logical properties, no fixed-width labels, truncate + tooltip; RTL-ready CSS even though no RTL
  language ships now.
- Pseudo-locale (accented, +40% length, bracketed) in dev and in one e2e smoke test.
- `lingui extract --clean` + `lingui compile --strict` check: a node test fails when extracted catalogs are stale;
  missing wave-1 translations block a release, not every commit.
- No TMS: translations live in the repo; LLM draft bound to the glossary; native review through pull requests.
- Translator context: `comment` and `context` on ambiguous messages (written to the PO file).

## photobaer-specific rules
- Stable IDs: menus, context menus, command search, Actions, scripting/agent bridge (webmcp, mcp/), shortcuts and
  saved workspaces keep English IDs; only the displayed label is translated. Recorded Actions/scripts must work
  after a language switch (test).
- Command search matches localized and English names.
- Number input: decimal separator follows the locale (German Photoshop shows 0,5) and NumberInput accepts both
  "," and "." when parsing. Scripting/API stays locale-independent.
- Shortcut display uses localized modifier names (de: Strg, Umschalt); key bindings stay identical.
- PSD files: layer names, blend-mode keys, file data never translated; default new-layer names ("Layer 1") are
  localized like Photoshop ("Ebene 1").
- Engine (Rust/WASM) error text: map error codes to messages in the app, not in Rust.
- Service worker precaches every catalog: a new release's catalog must be cached before the next offline start
  (decided 7 October 2026; precaching only the active one breaks the first offline start after an update).

## Glossary
- ~300 core terms per language (menus, tools, panels, blend modes, adjustments, filters) in that language's
  Photoshop wording, built from Adobe's public help pages term by term. Never import Adobe resource files.

## Language picker (user decision 7 October 2026)
- Flags only, in the menu bar between Donate and Fullscreen (`app/src/shell/LanguagePicker.tsx`), 20x13 px.
  Own SVG flags (English = United Kingdom). Each flag has title and aria-label with the language's own name.
- Choice saved in localStorage `photobaer:language`, applies by reload. Dev lists all 12; builds list `RELEASED`
  (`app/src/i18n/index.ts`) and hide the picker while only English is released.

## Phase 3 extraction rules
- JSX text: `<Trans>` (`@lingui/react/macro`). Strings computed at render or call time: `t` (`@lingui/core/macro`).
  Module-level tables: `msg` descriptors, shown with `i18n._(d)` at use time; never `t` at module scope (it runs
  before the locale loads). Interpolate plain variables (named placeholders); `plural()` for counts; one message
  per sentence, no concatenated fragments; `msg({ message, context })` for ambiguous words (Fill, Stroke, Clear).
- Menu items: `{ ...tl(msg\`Label\`, checked?), keys, run }` (`app/src/app/helpers.ts`). Interpolated English text:
  `{ id: \`Quick Export as ${f}\`, label: t\`Quick Export as ${f}\` }`. User data (file, layer, workspace names) as is.
- Never translate values that are compared, stored or sent: `client.call` arguments (history labels passed to the
  engine: messages pass maps them), ids, option values, localStorage keys, blend-mode keys, shortcut strings.
  `run(label, …)` busy text is display only: `t`.
- Engine-provided text (filter names and parameters, error text) maps by id in the app: `app/src/filters/labels.ts`.
- Guards: `app/src/app/menuTree.test.ts` (English menu tree snapshot, `UPDATE_MENUS=1`) and
  `app/src/i18n/hardcoded.test.ts` (per-file count of hard-coded strings, only shrinks, `UPDATE_BASELINE=1`).

## Phases (each its own commit series, English UI unchanged until phase 6)
0. Spike (half a day): Lingui 6 macros through Vite 8 + plugin-react 6 in dev and build; `node --test` on .ts modules
   that hold labels (Node runs no macro transform: plain .ts tables use runtime `i18n._(msg)` descriptors
   with explicit IDs or lazy label functions; prove extraction still finds them). Stop and report if this fails.
1. Infrastructure (TDD): i18n setup, catalog loader, locale negotiation, flag picker (applies after reload),
   html lang, pseudo-locale (Lingui `pseudoLocale`), SW catalog handling, extract/compile check.
2. Stable-ID audit: Actions, scripting, command search, workspaces, shortcuts decoupled from labels; tests.
3. Extraction by area: menus/context menus/tools/tooltips > panels > dialogs > options bar > messages/errors.
   Lint test against new hard-coded visible strings in .tsx.
4. Locale-aware numbers: NumberInput parsing/formatting, units, percent.
5. Layout hardening with pseudo-locale; CJK font stack.
6. Wave 1 translations + review; release. 7. Wave 2.

## Out of scope unless decided
- Static marketing/legal pages (app/public/*): per-language pages, hreflang, sitemap; legal review per language.
- RTL languages (ar, he).
- Localized documentation (docs/scripting.md).

## Risks
- Large mechanical diff across ~57 components: merge conflicts with feature work; done per area.
- Node test runner cannot run Lingui macros: phase 0 proves the pattern for .ts label tables before extraction.
- New dependencies (4 Lingui packages): third-party notices via scripts/third-party.mjs; license check (MIT).
- Actions/scripts bound to labels break on language switch: phase 2 before phase 3.
- Locale decimal comma breaks numeric entry or scripts if parsing is not dual: phase 4 tests.
- Outside translators send PRs; they must sign CLA.md.
- Independent review required for phases 2 and 4 (public scripting interface, saved Actions/workspaces).

## Rollback
- English default and stable IDs unchanged; languages are opt-in via picker. Revert = remove catalogs and picker;
  English source text in `<Trans>`/`t` still renders English.
