# M1 Layers and PSD: spec

Milestone text and gates: `docs/PLAN.md` sections 4 and 5. Owner decisions (25 September 2026):
- CPU and GPU compositor both in M1. The GPU compositor is WebGPU only; WebGL2 keeps CPU display tiles.
- Document state (layer tree, props, tiles) lives in the Rust engine; the worker keeps undo history.
- PSB and 16-bit PSD are deferred (ag-psd 31.0.2 supports neither); opening one gives a clear error.
- Text, adjustment, smart object and effect layers import as their stored raster, with a warning.
- Display tiles composite from a per-layer pyramid (owner, 25 September): every layer and mask tile keeps
  reduced copies per level (not saved). Level L display tiles composite the layers' level-L tiles, on the CPU
  and on the GPU alike. Exact at level 0; zoomed out it is a mipmap approximation. Flatten, export, PSD
  composite and the corpus oracle stay exact (level 0).

Clean-room sources only: W3C Compositing and Blending Level 1, the public Photoshop user guide,
the public Adobe PSD file format spec, ag-psd's own docs and types. Never open the reference app's app.asar,
its bundles, or any a separate tool extracted file.

## 1. Layer model (engine)

Tree of nodes. Every list of children is ordered bottom to top (index 0 is drawn first).

| Field | Pixel layer | Group |
|---|---|---|
| `id` u32, unique, > 0, never reused within a document (`next_node_id`) | yes | yes |
| `name` | yes | yes |
| `visible` | yes | yes |
| `opacity` f32 0..=1 | yes | yes |
| `fill` f32 0..=1 | yes | yes, acts like opacity (corpus) |
| `blend` | 27 modes, default `normal` | 27 modes or `pass through` (default) |
| `clipping` bool | yes | yes |
| `locks` { transparency, pixels, position } | yes | yes |
| `mask` optional { tiles, default: 0 or max, enabled } | yes | yes |
| `tiles` (RGBA, doc depth) | yes | no |
| `children` | no | yes |

Blend mode names are the ag-psd strings: `normal`, `dissolve`, `darken`, `multiply`, `color burn`,
`linear burn`, `darker color`, `lighten`, `screen`, `color dodge`, `linear dodge`, `lighter color`,
`overlay`, `soft light`, `hard light`, `vivid light`, `linear light`, `pin light`, `hard mix`,
`difference`, `exclusion`, `subtract`, `divide`, `hue`, `saturation`, `color`, `luminosity`,
plus `pass through` (groups only).

Masks are single-channel tiles at document depth (new `Pixels` variants). A missing mask tile has
the value `default`. Pixel and mask tiles share one copy-on-write tile id space. Layer pixels are
limited to the document canvas in M1 (PSD content outside the canvas is cropped on import).

A new document has one pixel layer "Background" with id 1.

## 2. Manifest v2 and project files (persistence: review gate)

```
{ format: "photobaer-manifest", version: 2, width, height, depth, tiles_x, tiles_y,
  next_id, next_node_id, layers: [Node] }
Node = { id, name, kind: "pixel" | "group", visible, opacity, fill, blend, clipping,
         locks: { transparency, pixels, position },
         mask: null | { enabled, default, tiles: [id] },
         tiles: [id]          // pixel only, length tiles_x * tiles_y, 0 = empty
         children: [Node] }   // group only
```
- The reader accepts v1 (flat `layers` with name/visible/opacity/tiles): each becomes a pixel node,
  ids 1..n bottom to top, fill 1, `normal`, no mask, no locks. Old autosaves and .pbaer files open.
- Reject: duplicate node ids, node id 0, `next_node_id` <= max node id, unknown blend,
  `pass through` on a pixel node, a tile id used both as RGBA and as mask, ids > 2^53,
  wrong tile array length. Loading validates tile byte length per kind (RGBA or mask).
- `project.ts` `tileIds()` collects pixel and mask tile ids from the whole tree, for v1 and v2.
  The .pbaer container format itself does not change.

## 3. Compositor (CPU reference)

Premultiplied f32 RGBA per tile. Blend functions work on straight (unpremultiplied) color in 0..1.

**Pixel layer** over backdrop (premultiplied `cb`, alpha `ab`, straight `Cb`):
`As = a * mask(x,y) * opacity * fill` (mask counts only when enabled).
W3C general formula: `Cm = (1 - ab) * Cs + ab * B(Cb, Cs)`,
result `co = As * Cm + (1 - As) * cb`, `ao = As + ab * (1 - As)`.

**Dissolve:** the pixel is drawn fully opaque (normal) where `hash(doc_x, doc_y, node_id) < As`,
else not drawn. The hash is deterministic and stable across tiles and levels.

**Group, pass through:** `R = composite(children, backdrop)`; the output is the premultiplied lerp
`backdrop + (R - backdrop) * opacity * fill * mask(x,y)`.
**Group, other mode:** `G = composite(children, transparent)`; draw `G` onto the backdrop like a pixel
layer with the group's mode and `As = aG * opacity * fill * mask(x,y)`.

**Clipping group:** a non-clipped node B followed by one or more consecutive clipped nodes C1..Cn.
`S(x,y)` is B's coverage: `a_B * mask_B` (for a group, `a_B` is its children composited from transparent).
B's share of the pixel is divided by S, each visible Ci draws onto it with its own mode and
`As = a * mask * opacity * fill` (no shape factor), and the result is multiplied by S again. At full
base fill this is source-atop: clipped color covers the whole base shape and the base alpha is kept.
- B not pass through: B's share is `G`, B drawn from transparent with `normal`, `As = a * mask * fill`.
  The re-multiplied share is drawn onto the backdrop with B's mode and B's opacity.
- B pass through (stays in place, non-isolated): `S` also includes B's opacity and fill; B is drawn in
  place to `R`, B's share is `R - (1 - S) * backdrop`, and the output is `(1 - S) * backdrop + share`.
  Clipped nodes therefore blend with the in-place color.
If B is hidden, its clipped nodes are hidden. `clipping` on the lowest node of a list is ignored.
Verified on the corpus (clipping-mask, clipping-mask4, clipping-mask5, passthrough_clipping_mask_blendmode).

**Blend functions** `B(Cb, Cs)` per channel unless noted; clamp results to 0..1:

| Mode | B |
|---|---|
| normal | Cs |
| multiply | Cb * Cs |
| screen | Cb + Cs - Cb * Cs |
| overlay | hard light with Cb and Cs swapped |
| darken / lighten | min / max |
| color dodge | Cb = 0: 0; Cs = 1: 1; else min(1, Cb / (1 - Cs)). Endpoint tests use EPS 1e-5 (f32 unpremultiply of 255 is 0.99999994) |
| color burn | Cb = 1: 1; Cs = 0: 0; else 1 - min(1, (1 - Cb) / Cs). Endpoints with EPS as color dodge |
| hard light | Cs <= 0.5: multiply(Cb, 2Cs); else screen(Cb, 2Cs - 1) |
| soft light | W3C formula (D(Cb) piecewise at 0.25). Photoshop may differ: verify on corpus |
| difference | abs(Cb - Cs) |
| exclusion | Cb + Cs - 2 * Cb * Cs |
| linear burn | max(0, Cb + Cs - 1) |
| linear dodge | min(1, Cb + Cs) |
| vivid light | Cs = 0: 0; Cs <= 0.5: 1 - min(1, (1 - Cb) / 2Cs); Cs = 1: 1; else min(1, Cb / 2(1 - Cs)). Endpoints follow Cs, not W3C burn/dodge (corpus) |
| linear light | clamp(Cb + 2Cs - 1) |
| pin light | Cs <= 0.5: min(Cb, 2Cs); else max(Cb, 2Cs - 1) |
| hard mix | Cb + Cs > 1: 1; Cb + Cs = 1: 1 if Cs <= 0.5; else 0 (corpus; a few 8-bit samples at sum 255/256 fit no formula) |
| subtract | max(0, Cb - Cs) |
| divide | Cs = 0: (Cb = 0 ? 0 : 1); else min(1, Cb / Cs) |
| darker color / lighter color | whole color with the lower / higher W3C Lum (0.3, 0.59, 0.11); a tie keeps Cb (corpus) |
| hue, saturation, color, luminosity | W3C non-separable (Lum, ClipColor, SetLum, Sat, SetSat) |

Fill vs opacity: in M1 both multiply coverage for every mode and node kind. Open: a pass-through group
with fill < 1 over a lighter color child near a Lum tie gives a partial mix in Photoshop that no binary
choice explains (passthrough_fill_blendmode.psd, mean dE 1.375, max 4.27). Below the tie Photoshop moves
toward the source by `r * fill * a`, with r falling from about 0.47 to 0.37 as `a` rises; the corpus has one
fill value only, so no model is chosen. Needs Photoshop files at several group fill values.

**Oracle policy (tests/corpus.ts):** pixels where a visible dissolve layer has partial coverage are
excluded (Photoshop's pattern is random); a dissolve group skips the file. `EXCEPTIONS` names files
with a bounded count of pixels at dE >= 5 and/or a raised mean limit, and the measured reason.

**Draw program (`display_program(level, tx, ty, known)`):** one display tile as a stack machine over
premultiplied f32 RGBA buffers (the bottom of the stack is the output) plus a stack of single-channel
shape buffers. `src = 0` means the top buffer, any other value is a payload key; `mask_kind` is 0 full,
1 `mask_const`, 2 the `mask` tile. Only pixels inside `vw` x `vh` are touched by `Draw`, `PopLerp` and
`PushShape`; the whole tile by the shape and backdrop ops. 8-bit documents only (16-bit is an error).

| # | Op | Effect |
|---|---|---|
| 0 | `Draw` | draw `src` (popped when 0) onto the top with `mask`, `scale`, `mode`, `node` (dissolve hash) |
| 1 | `PushTransparent` | push a transparent buffer |
| 2 | `PushCopy` | push a copy of the top |
| 3 | `Pop` | drop the top |
| 4 | `PopLerp` | pop `R`; `top += (R - top) * scale * mask` (pass-through group) |
| 5 | `PushShape` | push `S = alpha(src) * mask * scale` |
| 6 | `DivShape` | `top /= S` (0 where `S = 0`) |
| 7 | `MulShape` | `top *= S` |
| 8 | `SubBackdrop` | `top -= (1 - S) * under` (the buffer below the top) |
| 9 | `PopAddBackdrop` | pop `G`; `top = (1 - S) * top + G` |
| 10 | `PopShape` | drop the top shape |

Binary layout, little endian: header `version=1, level, ox, oy, vw, vh, step_count, payload_count`
(8 x u32), then one 32-byte record per step (`u8 op, u8 mask_kind, u8 mode index, u8 pad, u32 node,
f32 scale, f32 mask_const, u64 src, u64 mask`), then per payload `u64 key, u32 kind (0 RGBA8,
1 mask8), u32 length, bytes`. `known` keys are referenced but their bytes are left out. Payload keys
are level-0 tile ids, or for a reduced tile the mix of its level, mask default and the level-0 tile
ids under it (top bit set), so any edit yields a new key, a content cache never goes stale, and a
cache hit costs no rebuild of the subtree.

The GPU compositor (WGSL) implements the same table and must match the CPU display path within 1/255 at
8-bit, at every level (both composite the same pyramid level). It keeps a byte-bounded LRU of payload
tiles and sends the keys it holds as `known`; an evicted key is simply asked for again. WebGL2,
16-bit documents and a lost device fall back to the CPU `displayTile`.

## 4. Engine commands (by node id)

- `add_layer(name, above)` / `add_group(name, above)` -> id. Inserted directly above node `above`
  in its parent; `above = 0` means top of the root list.
- `group_nodes(ids)` -> id: all ids share one parent; the new group sits where the topmost was,
  children keep their order. `ungroup(id)`: children replace the group at its position.
- `delete_node(id)`: error if the root list would become empty.
- `duplicate_node(id)` -> id: deep copy above the original, new node ids, name + " copy", tiles shared.
- `move_node(id, parent, index)`: `parent = 0` is root; error if `parent` is `id`, a descendant of
  `id`, or not a group. `index` is the position after removal.
- `set_props(id, partial JSON)`: name, visible, opacity, fill, blend, clipping, locks, mask_enabled.
  Validate ranges and `pass through` only on groups.
- `add_mask(id, reveal)` (error if one exists), `delete_mask(id)`.
- `fill(id, target, rgba)` and `invert(id, target)`, target `pixels` or `mask`.
  Pixels: error on a group, error "layer pixels are locked" if `locks.pixels`. With
  `locks.transparency`, fill keeps each pixel's alpha and leaves empty tiles empty.
  Mask: fill uses the red channel as the mask value; invert maps v -> max - v and flips `default`.
- `set_tile_rgba8(id, tx, ty, data)`, `set_mask_tile8(id, tx, ty, data)` for importers.
- `layers_json()`: the tree for the UI (manifest fields without tile arrays; mask as
  { enabled, default } or null).

## 5. Worker API (task 3)

The UI addresses nodes by id. `command` gains the node id and target; new calls wrap section 4.
`DocInfo` gains `layers` (the tree) so every reply refreshes the panel. Every mutating call is one
history step with a label (e.g. "New Layer", "Blend Mode", "Delete Layer").

## 6. PSD (tasks 4 to 6)

Open with ag-psd `readPsd` in the worker using `useImageData: true` (no DOM in the worker).
Map groups, pixel layers, masks (`defaultColor`, `disabled`, mask rect positioned in document
space), blend mode, opacity, `fillOpacity`, `clipping`, `hidden`, `protected` (transparency,
composite -> pixels, position). Save with `writePsd`, including the merged composite from the CPU
compositor. Oracle: `pnpm corpus` renders through the engine and compares with the embedded composite.
